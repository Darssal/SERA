# SERA：启动与核心演示链

2.1.0 新增社区第四栏。官方活动、用户发布与评论、普通用户申请管理、官方逐人授权与撤权的完整演示见[社区说明](COMMUNITY.md#课程演示顺序)。本机官方课程账号凭据在私有目录，不写入演示文稿、源码包或录屏。

本文面向课程演示和功能验收，按当前 Flutter 原生页面、账户服务和平台能力组织操作。编号 01–55 对应原设计页；登录、注册、账户、验证邮箱与找回密码使用独立路由。页面目录只用于检查覆盖范围，真实流程应从对应功能入口开始。

这里列的是可执行步骤和观察点，不把“有界面”“请求已提交”当作系统日历、通知或语音已经验收。最终运行环境、构建产物、截图和实测边界以 [交付记录](DELIVERY_V2.md) 为准；逐项范围见 [完整开发与验收追踪](FULL_DEVELOPMENT_PLAN.md)。

## 启动前准备

- 在 `sera_flutter` 目录执行下列命令。推荐工程当前使用的 Flutter 3.47.2 stable / Dart 3.13.2；Android 还需要 Android SDK、Java 和可运行设备。版本、目录与正式部署参数见 [README](../README.md)。
- 完整演示使用账户模式。准备两个不同的测试账户 A、B；账户新建后没有预设业务任务。平台权限由用户实际授予。
- AI 目标拆解与“录完后识别”的云端备用方案需要服务端供应商配置。密钥只由后端读取，不写入 Dart、Web 产物、录屏或命令中的 `--dart-define`。
- 默认“实时转写”使用独立的本地 sherpa-onnx 服务及已校验模型。首次安装会下载模型；模型来源、大小、校验和、单独启动方式见 [本地 ASR 说明](LOCAL_ASR.md)。文件录音识别还需要后端可调用 `ffprobe` 核验音频。
- Web 完整流程推荐同源地址 `http://127.0.0.1:8787/`，使用浏览器支持的安全上下文。公开部署应使用 HTTPS，并让浏览器能访问配置的 WSS 地址。不要把 `localhost` 与 `127.0.0.1` 混为同一个站点。

### 一键启动 Web、API、工作进程与实时 ASR

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\start-fullstack.ps1
```

`setup.ps1` 安装锁定的 Flutter/Python 依赖、下载校验实时识别模型，并准备本机发布签名。`start-fullstack.ps1` 编译同源 Web，由监督进程启动主服务 **8787**、持久作业/推送 worker 和实时 ASR **8790**；关闭时按 `Ctrl+C`。准备好依赖和现有 Web 构建后，可加 `-SkipBuild` 复用产物。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-fullstack.ps1 -SkipBuild
```

浏览器打开 `http://127.0.0.1:8787/`。未登录时进入登录页，登录后显示自己的工作空间。已有供应商密钥文件可通过 `-AiKeyFile <文件路径>` 指定；脚本也会检查工程上级的既有配置文件，绝不把内容输出到页面。SMTP、本地邮件、健康检查与 API 参数见 [接口说明](API.md)。

如需排查三个独立进程，在三个终端中分别启动，并让它们使用**同一个数据库路径**：

```powershell
# 终端一：API 与已构建 Web
.\backend\.venv\Scripts\python.exe backend/server.py --host 127.0.0.1 --port 8787 --db backend/sera.sqlite3 --web-dir build/web

# 终端二：持久作业与推送调度
.\backend\.venv\Scripts\python.exe backend/worker.py --db backend/sera.sqlite3

# 终端三：本地实时识别
.\backend\.venv\Scripts\python.exe backend/local_asr.py --host 127.0.0.1 --port 8790 --db backend/sera.sqlite3
```

分进程启动仍需按 [API 配置](API.md) 设置供应商、ASR 地址和邮件模式。主服务存活不代表 worker 或识别模型已就绪；检查 `/health/ready` 的分项结果。

### Android 与 MuMu1

先启动上述完整后端，再连接设备。此环境 MuMu1 的 ADB 地址为 **127.0.0.1:16416**：

```powershell
adb connect 127.0.0.1:16416
adb devices -l
adb -s 127.0.0.1:16416 reverse tcp:8787 tcp:8787
adb -s 127.0.0.1:16416 reverse tcp:8790 tcp:8790
powershell -ExecutionPolicy Bypass -File .\scripts\run-android.ps1 -Device 127.0.0.1:16416
```

启动脚本默认自动为选中设备反向映射这两个端口；上面的显式命令便于排查连接。Android 模拟器或真机若改用电脑局域网地址，需要相应调整 `-ApiBaseUrl`、服务监听地址和 `SERA_ASR_WS_URL`。仅开放 8787 不能完成实时转写。

### 构建与时间基准

完整参数和签名管理按 [README 的启动与构建说明](../README.md) 执行，常用脚本如下：

```powershell
# 同源 Web
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1 -Target web

# 课程安装用调试 APK
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1 -Target apk -Debug

# 需要真实发布签名；外部部署使用实际 HTTPS 服务地址
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1 -Target apk -AndroidApiBaseUrl https://<你的服务域名> -HideReview
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1 -Target aab -AndroidApiBaseUrl https://<你的服务域名> -HideReview
```

Web、APK、AAB 分别输出到 `build/web/`、`build/app/outputs/flutter-apk/`、`build/app/outputs/bundle/release/`。Release 构建要求独立签名配置；`-HideReview` 隐藏课程页面目录。以上是命令示例，实际产物和通过结果以交付记录为准。

应用默认使用真实时钟和账户偏好中的时区。仅为了对照设计截图，可在重新编译时使用 `start-fullstack.ps1 -DemoDate 2026-10-28`；该参数不会清空或重写已有数据。正常业务演示建议保持真实日期，并选择未来的截止时间。

## 演示一：账户、首次设置与身份隔离

**前提：**主服务可用；邮箱流程使用已配置 SMTP、Mailpit，或明确选择的本地开发邮件模式。准备 A、B 两个测试身份。

1. 在登录页点击“还没有账户，去注册”。填写 3–40 字的用户名、有效邮箱及 10–128 字的密码，点击“创建账户并开始”。错误输入应留在表单并显示原因，不能进入伪登录状态。
2. 新账户首次进入 02“你的节奏”，选择可安排日、专注时段和每日预算，点击“继续，连接已有日历”。03 可以实际连接日历，也可直接点击“继续，查看今天”完成首次设置；之后重开应用不应重复强制引导。
3. 打开“我的”30，核对真实用户名，进入“账户与安全”。账户页显示当前邮箱与验证状态。退出后重新登录或关闭页面再打开，核对恢复的是同一个账户和工作空间。
4. 未验证邮箱点击“验证电子邮箱”→“发送验证邮件”。打开邮件中的链接，或在验证页输入邮件里的凭证并确认。返回账户后应更新状态。开发模式邮件写在服务端数据目录的 `mail` 子目录；这只代表本机投递，不代表邮件已发送到外部邮箱。
5. 退出后在登录页点击“忘记密码”，输入注册邮箱；通过邮件链接设置新密码。完成后使用新密码登录，并检查旧会话已失效。不要在演示录屏中展示邮件凭证或会话信息。
6. 如有 v1 数据，在账户页点击“检查可迁移的旧数据”。分别查看“此设备旧数据”和“旧服务数据”的预览，再选择“预览并导入…”；必须核对覆盖范围并确认“确认替换并导入”，才会替换当前账户内容。先导出需要保留的资料；没有旧数据时显示真实空结果。
7. A 创建一个独有任务和未提交的规划输入后退出，登录 B：任务、规划记录、离线队列和日历映射应属于 B；再登录 A，检查 A 的内容恢复。通知与日历测试同样必须在当前账户下执行。

**失败与恢复：**错误密码、过期邮件凭证、限流或网络失败应显示原因并允许重试。重置密码请求不会暴露某邮箱是否注册。账户恢复失败时使用实际重试入口；未恢复身份时不要继续写入另一个工作空间。删除账户只用于最后的测试身份，并走演示七的密码和二次确认。

## 演示二：文字目标 → 真实计划 → 编辑草案 → 正式安排

**前提：**账户已登录，服务端 AI 配置可用；偏好 31 中有足够可用时段。用未来 10–14 天的截止时间，避免当天剩余容量不足掩盖主要流程。

1. 在“今天”04 的空输入框写入目标，例如“下周五前完成一段三分钟的产品介绍视频，每天最多投入 60 分钟，需要写稿、录音和剪辑”。样例只应出现在提示文案里，不能成为已输入内容。点击发送进入 05，核对原始描述与当前目标一致。
2. 点击“继续，补充目标要求”进入 06。确认目标名称、截止日期和时刻、每日预算与补充条件。日期是可解释的简单规则提示：支持今天/明天/后天、本周/下周/周几、`YYYY-MM-DD` 或 `M月D日`，默认时刻 15:00。以 2026-10-28 或 2026-10-31 为今天时，“下周五”均应提示 2026-11-06 15:00；未识别或无效日期会标注待确认，暂用七天后，请手动改正。新目标不能沿用上个目标的截止。
3. 点击“生成可执行的计划”。07 展示真实生成阶段，等待服务端任务拆解、结构检查、忙闲/预算/截止约束排期与草案保存。完成后自动进入 08；任务数量、总时长及模型来源来自实际结果。需要取消时使用生成中的取消入口，不能把取消当作成功。
4. 在 08 核对任务是否贴合输入、每项完成标准和时间比例。打开任务进入 09，修改名称、估时、完成标准、排期或是否暂不安排并保存；返回后核对修改保留。调整顺序或重新检查安排，再确认所有草案项仍然存在。此时正式任务列表和日历尚未新增这些草案任务。
5. 点击“下一步，确认写入”进入 10，核对实际数量和目标。点击“确认创建…项任务与安排”后进入 51，等待实际提交成功再进入 11。查看任务与日历，刷新后检查目标、任务、时间块仍关联正确；再次打开并确认同一份已创建草案不能重复新增。
6. 在目标详情 21 修改目标信息或调整计划，经草案审核后点击“确认更新目标计划”，核对更新的是原目标及其任务。任务细化草案则显示“确认更新执行步骤”，应保留原任务身份，不能创建无关的新目标。
7. 在 05/06 输入后用页面返回、系统返回、切后台或稍后继续，再从“规划与变更记录”34 恢复。生成途中关闭应用后，选择“生成待继续”的记录，进入 07 点击“继续这次生成”，应继续读取原作业，不能新建另一份作业；如果原草案已经保存，点击“查看这次的计划草案”找回对应内容。核对本账户原始输入、手工修改和阶段；清理对话记录前确认影响，已确认的正式任务不应随对话清理消失。

**失败与恢复：**AI、容量或网络失败进入 39。暂时断网或状态查询失败可“继续这次生成”，保留原始请求条件；明确选择“重新生成一份计划”才新建请求。已失败或取消的作业可“重新生成计划”，也可“修改要求后再试”或“先手动创建一项任务”。接口模式不会静默改成本地模板。外部忙闲或对象版本变化时，48 保留草案并提示重新检查；先核对再提交，失败不应留下半份正式计划。确认按钮忙碌期间不能重复提交。

## 演示三：任务状态、依赖、多块安排、专注与回顾

**前提：**至少有一个目标任务和一项独立任务。专注演示使用真实等待时间，不通过完成操作伪造专注时长。

1. 打开任务页 17，切换“今天”“收件箱”“全部”“已完成”。点击右上角添加进入 19，填写标题、估时和说明，选择“先放入收件箱”或安排时间。截止可以仅选日期，详情应显示日期语义，不强制显示一个假的 23:59 截止时刻。
2. 展开“执行方式与前置条件”，设置任务状态、优先级、剩余工作量、允许拆分与最小时间块。选择前置任务，保存后在 18 核对；前置任务未完成时尝试开始后置任务，应提示阻碍。自依赖或依赖环必须拒绝保存。
3. 对允许拆分的任务编辑首块，添加、修改或移除“其他时间块”。核对每段长度、总工作量、截止、缓冲与冲突约束；可以只排一部分剩余工作。保存后日历显示全部时间块，重新编辑不应压成一块或丢失状态与检查项。
4. 在 18 勾选检查项，进入专注 25，暂停、继续，再选择“暂停并稍后继续”。关闭/重新打开应用，从“今天”的继续入口恢复；结束时保存真实累计秒数，进入 26，由用户确认完成或“还差一点，安排剩余时间”。结束计时本身不能自动把任务标为完成。
5. 在 24 跟进或 26 反馈卡住原因，保存受阻状态；选择拆解建议时，经真实生成进入 08 审核，再确认更新原任务执行步骤。中途关闭后，可从 34 继续原来那次生成；若原任务已经修改，先核对当前内容，再明确选择“按当前任务重新生成”，旧建议不能覆盖新版本，已删除或结束的任务不能继续生成。原 taskId、目标归属与已有工作量必须保留。需要补排时进入 47 调整剩余分钟，核对新建议后点击“确认安排剩余…分钟”。
6. 打开目标列表 20 的不同目标，核对 21 显示的是所点目标。编辑信息、暂停、恢复、完成验收或归档时使用各自明确入口；完成目标前先核对任务与验收条件。归档目标应能在归档区域找到。
7. 打开今日回顾 28 和本周回顾 29，对照当前任务状态、计划日期和真实专注记录。填写反馈后刷新，核对回顾保存；勾选任务完成不会自动增加实际专注时长。搜索 35 可找回任务、目标、日程、草案与规划记录。

**失败与恢复：**未保存的任务/日程编辑离开时应有放弃确认；选择继续编辑可保留输入。超预算、重叠、过去时间或无效分段要显示原因，不能覆盖原安排。专注保存失败允许重试；另一个任务仍在专注时先处理已有会话。删除对象或失效链接应提供返回列表入口。

## 演示四：日历来源、ICS、增量同步与安全重排

**前提：**Android 有可用 Calendar Provider，并实际授予日历读写权限；Web 准备一个无敏感资料的 ICS 文件。测试系统日历改动时记录操作前状态。

1. 在日历 12/13/14 切换周、日、月与前后月份，打开 15 查看对应事项。通过添加入口进入 16 新建固定日程，核对是新增而不是编辑列表第一项；再编辑标题、地点、跨日范围或全天状态。全天在账户时区按日期显示，跨时区/DST 场景应按实际日期边界核对。
2. 从“我的”30→“日历与同步”32，Android 点击“请求设备日历权限”，选择需要读取的日历，设置“自动同步已确认的安排”，点击“读取忙碌时间并同步安排”。选择的外部来源只读；忙碌时间参与之后的规划与提交检查。
3. 在系统日历检查当前账户的序日日历：新增、修改、删除一项应用内安排后同步，再重复同步，核对没有重复事件。42 查看每项实际结果；应用内保存成功和系统日历同步成功分别核对。
4. 在系统日历手工修改一条已由应用写入的事项，回到应用再次同步：应出现外部修改冲突，普通重试不覆盖。只有用户核对并二次确认“以应用内容覆盖系统改动”后，才按应用内容更新。
5. Web 或无设备日历的平台在 32 点击“导入 ICS 忙碌时间”，先查看解析预览和警告，再“确认导入”。复杂时区/重复规则由鉴权后端预览；无法解析应说明原因。重复导入同一来源应更新该来源，不叠加重复忙碌记录。点击“导出应用内日历 ICS”，在浏览器下载或 Android 文件保存对话框完成保存，再用外部日历核对日期、全天与重复实例。
6. 用外部会议或已导入忙碌时间制造真实冲突，从提醒中心或任务调整进入 22，检查旧时间与可用建议；23 比较变更，确认后 52 显示实际新安排。固定和锁定安排不能被自动移动；没有足够时段时应明确提示。
7. 立即撤销时核对原安排恢复；先再编辑相关对象后尝试旧撤销，53 应保护后续改动。重排后系统日历与提醒按新时间更新，平台补偿失败需要单独重试。

**失败与恢复：**拒绝权限进入 41 后可打开系统设置，授权后“刷新平台与权限状态”。设备缺少日历服务要显示真实不支持状态，可使用 ICS；不能显示假连接成功。部分写入失败在 42 点击“重新同步未完成变更”，只处理未完成项。取消文件选择或保存不应显示已导入/已导出成功。外部忙碌详情保持只读，修改须回原日历应用。

## 演示五：系统提醒、免打扰与 Web 后台推送

**前提：**有未来的任务时间块，设备/浏览器允许通知。Web 后台推送还需要浏览器支持 Push、有效订阅、服务端 VAPID/worker 和可达的推送服务；只出现“请求已排队”不能证明系统已经收到。

1. 从 30→“提醒与免打扰”33（首次开启也可由 54 进入），点击“开启或重新请求通知权限”，实际允许授权，再点击“发送一条测试提醒”。检查系统通知中心的真实展示，页面提示仅作为请求结果。
2. Android 若显示精确闹钟未允许，按“允许精确闹钟调度”进入系统设置后返回刷新。设置“启用任务提醒”“执行跟进”、免打扰时段，点击“保存并更新实际提醒”，核对实际提交/跳过数量与错误。
3. 在任务详情 18 的提醒入口或 45 设置开始前提醒。为测试准备短期未来任务，核对通知标题、触发时间、免打扰顺延和执行跟进。多块任务的每个有效块应有独立提醒，改期、取消或完成后旧提醒不应继续生效。
4. Web 支持时，在 33 点击“开启后台提醒”，等待浏览器授权和服务端订阅成功，再点击“测试后台推送”。关闭所有应用标签页后检查实际系统到达，点击通知应恢复当前账户的对应任务/跟进页。完全退出浏览器后的行为仍取决于浏览器和系统后台策略。
5. 打开提醒中心 27，点击“查看任务”“已了解”，在仍有效的待处理提醒上使用稍后入口。刷新后状态应保留；开始时间变化后的新提醒不能被旧时间的“已了解”状态误隐藏。通知点击指向已删除或不属当前账户的对象时，应安全返回提醒中心。
6. 关闭后台提醒或退出 A，登录 B，检查旧账户的提醒不会显示在 B 的任务里；再次启用时按当前账户和当前计划重算。

**失败与恢复：**拒绝通知权限可“打开系统或站点设置”后重试。订阅网络失败、精确闹钟缺失、推送服务不可达等应显示真实原因，不把前台计时当成已启用后台推送。没有后台订阅时按页面能力说明使用前台提醒；测试通过必须以系统实际收到与点击结果为证据。

## 演示六：真实语音 → 可编辑文字 → 目标

**前提：**登录账户，浏览器/Android 有麦克风；实时 ASR 8790 已加载模型并就绪。云端文件识别需要供应商和音频校验配置。

1. 从“今天”麦克风入口进入 50“说说你的计划”，默认选择“实时转写”。点击“开始录音”后才请求麦克风；实际允许，清晰说出目标、截止和每日投入，观察真实 partial 文字。实时模式在录音期间就会发送音频转写。
2. 点击“说好了，确认文字”，等待 final，修改“检查识别文字”中的识别错误，再点击“使用这段文字继续”。05 应显示修改后的完整文字，尚未创建任务；随后按演示二确认目标并生成。
3. 再进 50 选择“录完后识别”。录音结束后点击“完成录音，识别文字”，等待真实识别结果。发生上传/服务失败时保留录音，点击“重新识别这段录音”，或重新录制；这一路在结束录音后才上传。
4. 在录制途中点击“取消录音”或返回，检查麦克风指示停止，再次进入可以正常录制。取消识别不能把迟到结果写入新目标。切换账户时旧会话的录音和请求需要释放。
5. 拒绝麦克风后查看错误，使用“打开麦克风权限设置”授权并重试；也可直接在“也可以直接输入文字”中填写，点击“使用这段文字继续”。录音单次最多 60 秒，音频最多 10 MiB，服务端会核验真实容器与时长。

**失败与恢复：**实时连接中断时展示真实错误和已得到的文字，用户可编辑后继续或重新录制；最终结果未返回不能假称识别完成。服务未就绪、权限拒绝、空音频、超时、取消都不能创建任务或留下持续占用的麦克风。实时模式与文件模式应分别测试，文字输入不算语音链路通过。

## 演示七：离线队列、并发冲突、历史与数据管理

**前提：**A 已在线登录并读取过工作空间；准备另一个浏览器/设备登录同一 A。离线重开 Web 还需要应用资源已缓存，首次从未打开过的站点不能凭空离线加载。

1. 保持当前页面后断开网络或停止主服务，编辑已有任务、记录回顾或暂停专注。进入 40“保存与同步”，查看离线状态和待同步数量；内容先持久保存在当前账户。关闭/重新打开已缓存应用，检查输入、队列及记录仍在。
2. 恢复服务，通过 40 的重试入口同步。核对队列逐步清空、刷新后业务结果一致；“同步状态”展示真实模式或上次错误。离线期间不能生成新的服务端智能计划或识别语音，已有任务仍可操作。
3. 制造对象冲突：客户端一离线修改任务 X；客户端二在线修改同一个 X，并另新增无关任务 Y；客户端一恢复并重试。40 应显示 X 的本机/云端差异，保留待处理内容。
4. 选择“保留本机待同步修改”或“采用云端内容”，阅读二次确认中的影响再执行。前者只重放当前本机待同步批次，后者丢弃该待同步批次并采用云端；无关远端新增 Y 应保留。使用新的测试对象分别验证两条分支。
5. 打开“规划与变更记录”34，查看真实前后差异、恢复未完成规划；通过 35 搜索各类对象并打开正确上下文。36“数据与隐私”可检查平台入口和当前数据；清空工作空间或恢复演示数据前必须明确确认，不能拿正式账户做破坏性演示。
6. 账户页点击“读取账户数据导出”，核对数量和内容后“保存 JSON 备份”，实际选择保存位置或确认浏览器下载；也可“复制完整 JSON”。取消保存不应提示文件已保存。旧版本迁移仍须按演示一预览、备份并明确覆盖，不能自动认领。
7. 仅对专用测试账户，在账户页输入当前密码并确认删除。核对退出、旧会话失效、当前账户缓存及平台提醒清理；另一个测试账户的数据仍应存在。密码错误或用户取消不得提前清除身份与数据。

**失败与恢复：**队列同步失败保留本机修改，未解决的 409 不自动覆盖云端。非网络业务错误也应可见，不只写“已同步”。账号过期先恢复身份；切换 B 不能重放 A 的队列。先导出备份，再处理有损选择；真实导出、注销和平台清理各自记录结果。
