# SERA 主界面职责与操作路径分析

日期：2026-11-08。当前源码版本：2.0.14+16。

结论：当前混乱感主要来自页面职责、任务术语和操作入口的不一致。界面视觉已经较简洁，但用户仍需自行判断“这件事属于哪个页面、现在处于什么阶段、下一步从哪里做”。继续压缩间距与折叠内容，收益有限，还可能隐藏高频动作。

本次通过当前运行的 Web 预览实际访问四个主界面、任务列表与详情、目标创建入口及记录页，并核对当前源码。所有截图均在本轮新采集、保存后重新打开检查。只读浏览，未提交任务、修改账户或发送在线 AI 请求。临时浏览器页已关闭。以下不是 Android 验收、长列表性能测试或完整无障碍验收。

## 主要问题

### 1. 今日同时承担输入、规划、执行与回顾

今日包含 AI 输入、语音、添加待办、调整安排、对话记录、提醒中心、回顾、今日安排/今日待办切换与任务库入口。每个功能都有价值，但首页缺少明确优先级。

更关键的是，“今日待办”并不严格代表今天选定要完成的事情。当前查询会把没有未来开始限制、也没有未来时间块的未完成任务纳入，包括尚未排期、截止在未来的任务。未排期任务积累后，今日容易变成全部工作清单。

源码：[今日布局](../lib/ui/screens/main_screens.dart:142)、[今日待办范围](../lib/domain/todo_queries.dart:23)。

建议：今日优先回答“现在先做什么”。明确展示正在进行、下一项和今天要做的任务；未安排任务保留稳定入口或独立的“待整理”区，不全部混称今日待办。AI 保留便捷入口，但不应让执行内容成为首页的附属。

### 2. 任务没有稳定的家，名称又随入口变化

当前底部导航为“今日 / 日程 / 目标 / 我的”。任务库只能通过不同页面进入。

实际访问中，日程的“待安排任务”进入标题为“任务”的页面，分区又叫“收件箱 · 待整理”。今日同一位置的图标会根据列表模式变成“任务收件箱”或“全部待办”，本次相应数字从 1 变为 6。数字本身没有算错，但它们统计的是不同范围，界面没有稳定表达这种差别。

源码：[底部导航](../lib/ui/core/sera_widgets.dart:238)、[首页动态入口](../lib/ui/screens/main_screens.dart:323)、[任务列表与筛选](../lib/ui/screens/task_screens.dart:1100)。

建议：统一以“任务”为对象名称；完成状态使用“未完成 / 已完成”，时间安排状态使用“未安排 / 已安排”。给“全部任务”一个固定、带文字的入口。同一位置、同一图标保持同一个目的地。

### 3. 今日与日程缺乏足够明确的不同用途

二者并存合理，但当前都能表现为当天安排列表。今日更适合展示当前任务、下一步、完成与专注；日程更适合展示时间占用、空档、冲突、移动安排及固定事件。

建议：让今日以行动为主，让日程以时间为主。同一任务可以同时出现，分别突出“做什么”和“什么时候做”，无需删除合理的多视图。

### 4. AI 的入口承诺与结果类型不够清楚

今日“告诉我，你想完成什么？”进入 AI，目标“创建目标”也进入 AI；后者实际落到“一起安排 / 想安排什么？”的通用对话。用户需要重新推断当前是在聊天、创建任务、录入事件还是规划长期目标。

源码：[创建目标入口](../lib/ui/screens/main_screens.dart:888)、[AI 结果分支](../lib/ui/screens/planning_screens.dart:2191)。

建议：采用统一的 AI 助手入口和称呼。带目标上下文进入时，明确显示“规划一个目标”；模型输出后展示结果类型和将发生的变化，如“一项任务”“一项固定事件”“一个目标及 5 项任务”。语义理解继续由在线模型承担；这是交互说明的统一，不需要加入固定关键词识别。

### 5. 精简把部分核心操作也折叠了

当前未安排任务详情首屏有“标记任务完成”，但“调整时间”和“开始专注”收在更多信息中。源码显示已安排任务的专注操作直接出现在主体区域，而未安排任务的专注按钮在折叠区中。

这会让同一对象的操作位置随是否排期而变化，甚至让人误以为必须先排期才能专注。

源码：[直接展示专注](../lib/ui/screens/task_screens.dart:1463)、[折叠区内的开始专注](../lib/ui/screens/task_screens.dart:1546)。

建议：固定“开始专注 / 完成 / 安排时间”三个核心操作的位置；备注、依赖、同步信息、详细历史等低频信息可以折叠。长度是否合适应按任务需求判断，不按统一高度裁剪。

### 6. 对话、草案、操作记录的归属混在一起

“我的 → 规划与变更记录”落到“对话记录”，里面有对话、草案、操作。首页则直接把同一入口称为对话记录。用户寻找未保存方案或撤销操作时，很难从入口名称预判位置。

源码：[我的记录入口](../lib/ui/screens/main_screens.dart:1441)、[记录页标题及分类](../lib/ui/screens/planning_screens.dart:3688)。

建议：对话归 AI 助手，未提交方案明确归草案，撤销与变更归操作记录。可以保留互相跳转，但主名称要稳定。全局搜索应在业务页面具有可发现的入口，回顾宜就近放在今日和目标中。

## 推荐的第一轮调整

优先保留现有四个底部导航，先落实职责与入口一致性，减少用户重新学习成本。

| 主界面 | 唯一主要问题 | 重点内容与动作 |
| --- | --- | --- |
| 今日 | 我现在和今天先做什么？ | 当前与下一项、今日任务、开始专注、完成、日终回顾 |
| 日程 | 我的时间怎么分配？ | 日/周/月、空档、冲突、时间块移动、固定事件 |
| 目标 | 我在推进哪些长期结果？ | 目标进度、下一步、所属任务、整体方案调整 |
| 我的 | 账户和使用偏好怎么设置？ | 账户、通知、日历接入、AI 偏好、数据隐私、同步状态 |

任务库提供固定的“全部任务”入口；AI 作为统一助手可从相关业务带上下文打开。后续如果实测显示日常任务管理频率明显高于目标浏览，再评估“今日 / 任务 / 日程 / 我的”，把目标作为任务管理中的清晰一级切换。此次证据尚不足以断言必须更换底部导航。

统一对象关系：

```text
想法 ──手动或 AI 整理──> 任务 ──可选排期──> 日程中的时间块
                          ↑
                      可归属某个目标

今日：把这些对象中今天要执行的部分汇总出来。
草案：尚未确认的方案；对话：产生方案的交流记录。
```

应保留：目标—任务—多个时间块的数据关系；无目标或未排期任务；完整日历视图；复杂目标的必要信息；草案确认；冲突核对；专注结束的完成/剩余工作/遇到阻碍分支。

优先顺序：统一术语与固定任务入口 → 明确今日和日程分工 → 固定任务核心动作 → 统一 AI 上下文及输出说明 → 整理历史记录归属。完成后再判断是否需要调整主导航或继续压缩页面。

## 证据边界

此次判断基于实际看到的当前数据状态、只读导航与源码。未对新用户进行可用性实验，无法量化混乱程度或证明某种导航必然最优。今日待办的范围和已安排任务的操作差异有源码依据；没有通过修改用户数据构造边界场景。

从界面与语义树可确认图标存在辅助标签，但可见文字不足仍会影响首次发现。键盘完整路径、读屏实际朗读、放大字体和不同手机宽度未在此次分析中全面测试，不能据此宣称无障碍合规。
