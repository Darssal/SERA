# 后台运营统计口径与验收

版本 **2.2.1+33**，2026-11-10（香港时间）。官方在管理后台“概览”查看新增账号、发帖或评论人数、内容和评论趋势、内容分类，以及有互动的内容。统计只使用现有账号与社区记录，不读取个人工作区，不新增埋点、原始事件、第三方统计 SDK、数据库表或依赖。

本页记录实际数据定义和已完成的后端验收。完整 Flutter／界面交互、真实浏览器、主数据库对账与最终构建结果仍由主交付补入；未完成的部分不计为通过。

## 统计范围与时间

默认最近 **30 天**，可选 **7／30／90 天**。所有日期固定为 `Asia/Hong_Kong`，不随浏览器、手机或服务器所在时区改变。`generatedAt` 为本次服务端真实当前瞬时；生产没有固定演示日期，测试才冻结时钟。

| 字段或记录 | 单位和含义 |
| --- | --- |
| `users.created_at` | Unix 秒，账号注册时间 |
| `community_posts.created_at` | Unix 微秒，内容发布时间 |
| `community_comments.created_at` | Unix 微秒，评论发布时间 |
| `generatedAt`、`period.endAt`、`previousPeriod.endAt` | 带 `Z` 的 UTC ISO 8601 瞬时，保留微秒 |
| `startDate`、`endDate`、每日 `date` | 香港日历日期，`YYYY-MM-DD` |
| 点赞、报名 | 现有表没有发生时间字段，只能读取现存记录数量 |

当前期间从香港当天往前 `days - 1` 天的 **00:00:00** 起，包含起点，截止到 `generatedAt`，包含该瞬时；晚于截止的记录不计入该期间。用户时间按秒、内容与评论按微秒分别比较，不能把两种单位混用。每日以香港午夜划分，覆盖全部选中日期，没有记录的日期也返回零；今天尚未发生的数据不会补造。

前期开始为当前开始日期减 `days` 天，前期截止为 **当前截止瞬时减 `days` 天**，两段经过的时间相同。前期最后一天同样只统计到对应时刻，不多算余下半天。

例如香港时间 2026-11-09 12:30:00.123456 查看 7 天：

- 当前：11 月 3 日 00:00 至 11 月 9 日 12:30:00.123456。
- 前期：10 月 27 日 00:00 至 11 月 2 日 12:30:00.123456。

这里的 7 天表示 7 个日历日期，末日截至刷新时刻。跨香港午夜刷新时，日期窗口和最后一天自然前移；新一天为零是有效结果。

聚合与排行 DTO 在同一个 SQLite `BEGIN` 读取快照内完成。查询过程中即使另一连接写入，也不会在本次结果中混合新旧计数；下一次刷新才读到新快照。

## 指标定义与对账

| 指标 | 当前值 `value` | 前期值 `previous` |
| --- | --- | --- |
| 新增账号 `newUsers` | 当前期间内注册且仍存在的账号数量 | 同口径的前期数量 |
| 发帖或评论人数 `contributors` | 当前期间发布内容或评论的非空作者 ID 的并集，按账号去重 | 前期作者并集，独立去重 |
| 发布内容 `posts` | 当前期间发布且仍存在的日常、反馈及活动数量 | 同口径的前期数量 |
| 新增评论 `comments` | 当前期间发布且仍存在的评论数量，包括对较早帖子的评论 | 同口径的前期数量 |

“发帖或评论人数”反映已有发表行为，不代表访问人数、登录人数、日活、留存率或所有社区互动。仅点赞或报名的账号不会增加该人数。同一人在多天发帖、评论，期间人数仍只计一次；每日人数可以重复出现，因此不能把每日人数相加当作期间人数。

系统种子帖子如果 `author_id=NULL`，帖子会计入内容数量，但不产生一个虚构用户或贡献者。因此，存在内容却没有贡献者可以是合法结果。实际官方账号、管理员和普通账号发表的内容均按真实作者 ID 计数。

三类内容互斥：

1. `kind=activity` 为 **活动**，优先判断。
2. 其余 `category=feedback` 为 **使用反馈**。
3. 其余为 **日常动态**，包括官方动态。

分类按发布时间归入所选期间，不按活动将来开始的时间归入。三类数量之和等于该期间的 `posts.value`；每日新增账号、内容、评论之和分别等于对应期间指标。贡献者只要求与真实去重结果一致，不要求等于每日之和。前期与当前显示数量差，不在前期为零时制造无限增长率。

## 当前互动与排行

`currentInteractions.likes` 和 `currentInteractions.participants` 是**全站现存累计**点赞和报名数量，不随 7／30／90 天切换。原表没有完整发生时间，不能据此生成所选期间的点赞趋势、新增报名或前期互动比较。

排行先选择**所选期间发布且仍存在**的内容，再按该内容当前的点赞数、评论数和报名数之和排序。只返回互动之和大于零的记录，最多 5 条；同分以较新的内容序号优先。没有互动时返回空列表，不把零分内容排成“热门”。

排行条目的 `post` 使用现有 `CommunityPost` DTO，`interactions` 等于它的三个当前计数之和。相关数量用独立计数查询，避免把评论、点赞与报名直接多表 JOIN 后相乘。旧帖子仍可贡献全站累计互动，但不进入所选发布期间的排行。

## 现存记录与演示数据

这是现存记录的运营视图。删除帖子会同时清除其关联评论、媒体和互动；删除评论、取消点赞、取消报名后，下一快照相应数量会减少。注销账号及外键级联同样可能改变过去日期的现存计数。此版本没有不可变历史事件账本，不保证把已经删除的行为永久保留在历史曲线中。

种子内容、课程演示账号与明确标注的模拟帖子，只要仍在当前数据库且发布时间符合窗口，就正常计入。界面应明确这些内容的演示性质；不通过排除或造数把测试社区包装成真实运营增长。查看统计不会补建演示内容、改写发布时间或创建互动。

## 权限、API 与数据边界

新增只读接口：

```text
GET /api/v1/admin/analytics?days=30
```

仅服务端官方所有者可读取。普通用户、游客和即使拥有全部四项社区权限的管理员也不能读取。接口沿用现有 Bearer 或同源 HttpOnly Cookie／CSRF 认证传输，返回 `Cache-Control: no-store`；携带的旧账号 CSRF 不匹配时仍被拒绝。没有建立另一个后台账号或权限体系。

响应固定为：

```text
days, timeZone, generatedAt,
period {startDate, endDate, endAt},
previousPeriod {startDate, endDate, endAt},
summary {newUsers, contributors, posts, comments} -> {value, previous},
daily [{date, newUsers, contributors, posts, comments}],
contentTypes [{key, label, count}],
currentInteractions {likes, participants},
topPosts [{post: CommunityPost, interactions}]
```

`days` 只接受 7、30、90；缺省为 30。非法输入为 `400 invalid_admin_request`，无会话或过期为 401，非官方为 403。运行中的 `/docs` 与 `/openapi.json` 描述参数、响应、安全和 `no-store` 契约。

原有 REST 接口与 DTO 不做破坏性变更；后台实际端点由 9 个增加为 10 个。数据库 schema、身份迁移版本、workspace schema 2、社区表和持久数据格式不变。SQL 不读取 `account_workspaces`，不返回邮箱、手机号、密码、会话、私有文件路径或个人任务内容。排行复用本来就在社区公开的内容及作者显示规则。

## 图形呈现与可访问性

图形只表达上述实际数据；空值与读取失败分别呈现，不使用静态折线或占位统计。趋势图、账号柱状图与逐日表格共享同一份结果，选中日期应显示具体数量，刷新或切换区间后以响应日期和截止时间为准。

此版本复用 Flutter 原生绘制，不增加图表库。图例同时用颜色、实虚线和点形区分系列；图形配有语义说明、方向键／Home／End 日期选择与可读取的逐日数据。视觉、键盘、屏幕阅读及不同窗口宽度的实际结果仍需本轮主交付验收，代码存在不能替代设备或浏览器测试。

本轮核对的官方资料与适用结论：

- [SQLite 日期与时间函数](https://www.sqlite.org/lang_datefunc.html)：SQLite 没有专用日期类型，Unix 时间通常表示秒；SERA 显式区分秒与微秒，在应用边界按固定香港时区生成日界线，再用整数比较和分组，避免依赖主机本地时区或自动猜测单位。
- [Flutter CustomPainter](https://api.flutter.dev/flutter/rendering/CustomPainter-class.html)：绘制与重绘判断、命中和语义是不同职责。SERA 的少量趋势与柱形使用原生绘制，语义和键盘操作由相关 Widget 提供，不把图形像素当作完整的信息入口。
- [Flutter Accessibility](https://docs.flutter.dev/ui/accessibility)：信息须可由辅助技术访问，颜色也不应是唯一识别方式。SERA 同时保留文字数值、系列标记和逐日数据，并将实际无障碍检查列为发布前待验项。

## 简短演示

1. 官方账号进入 `/#/admin/overview`，查看默认 30 天，核对所显示的香港日期和截止时间。
2. 切换 7／90 天，观察期间指标、逐日数据和分类随窗口改变，全站现存累计点赞／报名保持同口径。
3. 选择趋势图中的某日，使用鼠标与键盘查看对应数值，并与逐日表格对照；打开排行内容，核对实际评论、点赞、报名与互动之和。
4. 在隔离演示库新发测试内容和评论后刷新，核对期间总数与分类；取消互动或删除测试内容，核对现存数量减少。不要对用户现有帖子试删或改写日期。
5. 用具有全部四权限的普通管理员请求统计，验证服务端拒绝；切换账号时不应继续展示上一官方会话的数据。
