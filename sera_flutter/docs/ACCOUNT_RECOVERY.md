# 邮箱验证与账号恢复

账号入口为 `/account`，登录页提供 `/forgot-password`。验证与重置邮件分别指向 `/#/verify-email?token=...` 和 `/#/reset-password?token=...`。完整接口、错误码和配置字段见 [API 文档](API.md#会话邮箱与账号)。

## 邮箱验证

1. 登录后进入账户页，点击“验证电子邮箱”，发送验证邮件。
2. 页面显示服务端实际返回的投递方式。`local` 表示邮件仅保存在本机；`mailpit` 表示开发收件服务接受；`smtp` 表示邮件已交给 SMTP 服务。只有实际收件证据才能证明邮件到达收件箱。
3. `local` 模式会读取当前账号有效的开发验证邮件，显示链接和有效期，点击“使用此链接验证邮箱”提交该链接的真实 token。也可展开“本地开发验证邮件”重新读取。该接口必须登录，不能指定其他账号，不能取得重置密码凭证。
4. 邮件链接在 Web 中预填凭证。Android 没有配置公网 App Link 时，可将完整邮件链接粘贴至“验证凭证或完整邮件链接”后确认。客户端只提取对应验证路由的 token，错误用途的链接不会发出请求。
5. 验证成功后重新读取 `/auth/me`，账户中显示已验证。若链接已确认但账户状态读取失败，点击“刷新验证状态”恢复，无需再次消费已经使用的链接。

验证邮件 30 分钟有效、单次使用；重发会立即作废原链接。过期、已使用或错误类型的 token 会失败，页面保留输入并允许重新发送；有效登录账号与链接账号不一致时拒绝操作且不消费 token。可退出错误账号后使用链接，或登录对应账号再验证。

## 找回密码

1. 在登录页点击“忘记密码”，输入注册邮箱并提交。
2. 申请响应始终保持通用，不说明邮箱是否注册、是否达到账号频次限制或是否出现发送故障。来源 IP 的独立限流返回 429，稍后可重试。
3. SMTP 模式下从本人收件箱取得邮件；Mailpit 开发模式使用本机收件服务。`local` 模式仅在受保护的服务端 `mail/` 目录保存邮件，需要本机部署管理员读取本人申请的链接；页面不会向匿名访问者公开重置 token。公开部署应配置真实 SMTP。
4. 打开邮件链接，或将完整链接粘贴至“重置凭证或完整邮件链接”，输入两次新密码。密码要求 10–128 个字符。输入错误、凭证失效或网络失败时保留表单，方便修正重试。
5. 成功后该账号全部旧会话和推送订阅失效；新密码可重新登录，原任务、目标、安排和工作区保持。当前设备清理旧会话元数据，登录页提示密码已重置。

重置申请受理不保证投递；后台发送在 API 进程中执行，服务在发送完成前被强制停止时需要恢复后重新申请。重发作废旧链接，重置 token 同样只有 30 分钟有效且单次可用。使用其他已登录账号确认链接会被拒绝，不影响原链接。

## 配置与运行

配置模板为 [deploy/.env.example](../deploy/.env.example)。本机启动脚本支持显式 `--env-file <私有路径>`，只加载允许的配置字段，不打印内容。真实私有文件须保存在发布包以外，不将 `mail/` 或密钥目录映射到静态站点。

- `SERA_MAIL_MODE`：`local`、`mailpit` 或 `smtp`。
- `SERA_PUBLIC_ORIGIN`：可访问的站点 origin，必须是 HTTPS 或本机 HTTP；不能包含路径、凭据、query 或 fragment。不使用请求 Host 生成安全操作链接。
- `SMTP_HOST`、`SMTP_PORT`、`SMTP_FROM`：SMTP 服务、端口、发件人；`SMTP_USERNAME` 与 `SMTP_PASSWORD` 须成对配置。
- `SMTP_TLS`：`starttls` 或 `ssl` 使用系统信任链验证证书及主机名；`none` 仅允许本机测试服务。非法值在建立连接前失败。

当前本机邮件链接的 origin 为回环地址，其他设备无法因此直接访问这台电脑的 Web 服务。需要跨设备打开时应部署可达域名和 HTTPS；原生粘贴完整链接可完成 token 确认，但不代表已配置 Android 邮件链接唤起。

## 本轮验证证据

2026-10-31 的账号后端和 AI 最新离线源码全套 92 项通过，使用临时数据库与随机回环 SMTP 收件器；覆盖账号隔离、重发/过期/消费、并发单次使用、SMTP 证书配置、防枚举、限流、故障、重启后状态保持和原工作区恢复。此前87项结果另行保留，最新运行增加5项内部提示词契约回归，不将提示词断言视为真实模型语义质量通过。

另在临时数据库中，通过已授权 SMTP 向授权邮箱自身发送两封项目邮件，并通过只读 IMAP 只读取本轮新发的 SERA 操作邮件：实际收到验证和重置邮件、消费邮件 token、刷新已验证状态、撤销旧会话、拒绝旧密码/重复 token、新密码登录及原任务内容和 ID 保持均通过。该记录属于外部邮件和后端接口验证；不代替 Flutter 页面、Web 和 Android 新版本测试。
