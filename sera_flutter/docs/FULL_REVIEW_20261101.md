# SERA 全盘要求复查与剩余验收

日期：2026-11-01，Asia/Hong_Kong。本轮基准为当前 **2.0.8+10** 源码及对应候选，不能以旧2.0.0/2.0.1交付状态代替。总协调对现有五个专项分别下发复查，并独立核对最初切图/H5、素材追踪和交付件版本。

**当前结论：主要功能已有真实实现和分层证据，但尚不能宣布全部要求完成或整版放行。** 本轮检查发现了需要修复的缺陷、需要补测的发布门槛和需要更新的文档，三者分别记录。没有改动产品代码，没有把“审计完成”当作“问题已修复”。

## 回顾用户要求

1. **设计与素材**：55张设计逐页拆解，保留导航、内容区、可复用组件、配色/字号/间距/圆角说明；文字、按钮、卡片用真实布局实现，复杂图像独立切图，清晰、透明、等比例并有命名与映射。
2. **H5及正式工程**：以已确认H5为基准，Flutter原生Widget覆盖Android与Web，公共组件/导航/状态/网络/持久化可复用；真实业务不能止于展示或模拟成功。交付启动、构建、目录、演示、部署和测试材料。
3. **原全量方案**：R01–R32、数据schema2、账号隔离、对象版本/幂等/事务、草案及排期、外部忙闲、撤销、专注和真实回顾；Android日历/系统提醒，Web ICS/SW后台Push；离线、多端冲突、备份和隐私。
4. **界面反馈**：有选择地精简冗长/重复信息，保留合理长页面和必要说明；后续简洁风、聊天与返回、待办日历、紧凑工作周、连续旅程/核心测试的具体要求也必须回顾。点击数、滚动成本和响应性能分别判断，不能改预算或删失败项凑通过。
5. **在线AI**：优先使用用户在线模型理解完整语义、意图与处理需求，减少关键词/固定范式；结构化契约与排期安全校验仍保留。未知日期不捏造，追问适量，澄清/校对/确认/取消/恢复与账号边界完整。后续模型、公共事实工具、长计划、协议/导入等要求以AI专项的逐项审计为准。
6. **真实账号能力**：邮箱验证/找回/会话/导出/注销，已授权SMTP真实接入；新增只选择PNVS短信认证，保留邮箱并处理身份绑定/自动进入应用/新旧账号兼容。QQ、微信、本机号码一键登录不因本轮复查变成必做。
7. **动画**：统一页面进退、弹层和状态过渡，保护对象ID、输入、焦点、滚动和返回，支持减少动态效果；用实际profile/release采样说明性能边界。
8. **验证与资源**：指定MuMu安卓设备-1（127.0.0.1:16416）；保护正式账号、数据、凭据及已有输入。关闭闲置测试环境，后续按需串行启动并回收；模拟、接口、编译、安装、平台实测、真人质量不得相互替代。

本轮未新增iOS、Google/Microsoft云日历、多用户协作、商店发布或公网部署采购等约定范围外事项。
